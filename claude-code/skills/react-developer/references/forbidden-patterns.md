# Forbidden Patterns

This project has no legacy code to migrate — any pattern below found in generated output was introduced in error. Fix it inline as part of whatever task touches that file; don't leave it for a follow-up.

| Forbidden Pattern | Why | Use Instead |
|---|---|---|
| Class components | React 19 code is 100% function components + hooks; classes have no compiler optimization and no hooks access. | Function components with hooks. |
| `forwardRef` for simple ref forwarding | React 19 passes `ref` as a normal prop — `forwardRef` is deprecated and slated for removal. | Accept `ref` directly in the props object (`function Input({ ref, ...props })`). |
| `componentDidMount`-style Effect misuse (an Effect that only fires once to "initialize" something unrelated to an external system) | Effects exist to synchronize with systems outside React (subscriptions, DOM APIs, network); using one as a lifecycle hook conflates rendering with side effects and often runs twice under Strict Mode in surprising ways. | Compute the value during render, or use an event handler if it's a response to user action. |
| `useEffect` to derive state from props/state | Causes an extra render pass (stale value, then corrected value) and is pure waste — the value is a function of existing inputs. | Compute the derived value directly in the render body (`const fullName = first + ' ' + last`), memoizing only if the calculation is expensive. |
| `useEffect` to reset state when a prop changes | Renders once with stale state before the Effect fires and resets it, causing a visible flash/flicker. | Give the component a `key={propValue}` so React remounts it with fresh state — see [keys-and-lists.md](keys-and-lists.md). |
| Unnecessary `useMemo`/`useCallback` for local referential stability | React Compiler (React 19's build-time optimizer) automatically memoizes values and functions where it's safe to do so, given components/hooks follow the Rules of React. Manual memoization for the same purpose is now redundant and adds noise. | Let the Compiler handle it. Reach for manual `useMemo`/`useCallback` only for the narrow cases the compiler can't cover — see [manual-memoization.md](manual-memoization.md). |
| PropTypes | Runtime-only type checking with no compile-time safety; this project is TypeScript-first. | TypeScript interfaces/types on props. |
| Array index as the `key` in a dynamic list | Index isn't a stable identity — reordering, inserting, or deleting shifts indices and causes React to misattribute state/DOM to the wrong item. | A stable field from the data (e.g. `item.id`), or an id generated once at item-creation time. See [keys-and-lists.md](keys-and-lists.md). |
| HOCs or render props as the default logic-reuse mechanism | Both add wrapper components/indirection and obscure prop origin ("wrapper hell"); custom hooks reuse stateful logic with a flat, traceable call site. | Custom hooks. Reserve HOCs/render props for the narrow exceptions documented in [hocs.md](hocs.md) / [render-props.md](render-props.md). |
| Redux/MobX boilerplate for simple global client state | Actions/reducers/selectors/dispatch add heavy ceremony for state that doesn't need time-travel debugging or middleware pipelines. | Zustand or Jotai — see [global-state.md](global-state.md). |
| Fetching in `useEffect` (manual `fetch` + `useState` for loading/error/data) | Reinvents caching, deduplication, retries, and race-condition handling that a data-fetching library already solves correctly. | TanStack Query — see [server-state.md](server-state.md). |
| `useEffect` for event-specific logic (e.g. showing a notification "because a value became true") | Runs whenever the condition is true on any render — including initial mount/reload — not only in response to the user action that's actually being described. | Put the logic directly in the event handler that causes it. |
| Prop drilling through multiple non-consuming intermediate components | Intermediate components become coupled to data they never use, and every consumer addition means touching every layer in between. | `children` composition, or Context for cross-cutting values — see [component-boundaries.md](component-boundaries.md). |
| Mutating state directly (`state.items.push(x)`, `state.value = x`) | React compares references to detect changes; mutating in place leaves the reference identical, so React may skip the re-render entirely. | Create a new array/object (`[...state.items, x]`, spread + override) with `useState`'s setter or an immutable-update helper. |
| Global mutable variables or module-level `let` used as de facto state | Bypasses React's render scheduling entirely — updates don't trigger re-renders and are invisible to DevTools/concurrent features. | `useState`/`useReducer` for local state, Zustand/Jotai for cross-tree state. |
| `useLayoutEffect` by default "to be safe" | Fires synchronously before paint and blocks the browser — appropriate only for measuring/mutating the DOM before the user sees it, not a safer default. | `useEffect` unless you specifically need pre-paint DOM measurement. |
| Deeply nested ternaries for 3+ way conditional rendering | Unreadable at a glance and error-prone to modify correctly. | A lookup object/map keyed by the discriminant, or an early return — see [rendering.md](rendering.md). |
| Inline object/array/function literals passed as props to memoized children, "fixed" by wrapping the child in `React.memo` without addressing the literal | `React.memo` compares props by reference; a new literal every render defeats the memoization it's meant to enable, while adding complexity. | Let React Compiler handle memoization of the literal at the source, or lift the value out of the render body if it's truly constant. |
